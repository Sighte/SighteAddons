# Quality Document

Current grades only. Update a row when the grade it carries actually moves; a session that changed
nothing here should not touch this file. **One row per domain** — until 2026-08-16 this table was
split into a "fresh" block and a "superseded" one below it, so `telemetry`, `scoring`, `history` and
`UI` each appeared twice and a stale row had already been mistaken for the current one.

There is no change history here. What a grade used to be, and why it moved, is in
`git log -p quality-document.md`; 14 dated entries are complete at `0852382`. Keep each cell to a
sentence or two: a cell that needs a paragraph is describing work, and work belongs in
`feature_list.json`.

**Grades:** **A** verification passing, clean, agent-legible, stable · **B** passing, minor gaps ·
**C** partially working, known gaps · **D** not working, or major structural issues.

**The ceiling on every grade below.** One real M7 is committed at
`docs/evidence/session-1786719912927/`, so calibration, room naming, core hashing and checkmark
reading have been seen working against live Hypixel data. For every path that run did not touch,
Loom's dev client still cannot log in, so "tests pass" means the logic matches its own model of a
dungeon rather than that the model matches Hypixel. And that run covered less than it looks like: it
was **solo and deathless**, so the decoration→player heuristic and the roster-skew blackout were
never exercised, no pixel of the `/sa` screen was seen, the `RED` checkmark never occurred, and
every room was scored under `clearpoints-001`'s deleted formula.
